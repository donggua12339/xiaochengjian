本文档定义小城笺加固产品线的**两条产品**——开源免费的**玄甲**与付费高级的**天衍**——的功能边界、技术架构差异、与竞品的对标、开发路线图。

## 4. 玄甲 · 反动态分析五层防护体系（X4 详述）

玄甲不使用自实现 Linker / VMP，但**防动态分析必须周全**。采用"五层纵深"，任何一层触发即 kill。哲学是"不靠藏，靠不让进"。

### 4.1 五层防护矩阵

| 层 | 防护 | 对抗的攻击 | 技术手段 |
|----|------|-----------|---------|
| **L1 反注入** | 阻止 Frida/Xposed 进入进程 | frida-server / frida-gadget / Xposed 注入 | 扫描 maps 中 `frida-agent`/`gadget`；检测 `/data/local/tmp/frida-server`；检测 Xposed 类加载器；检测注入 so 签名异常 |
| **L2 反调试** | 阻止 GDB/LLDB/IDA attach | 远程调试 / 本地 ptrace | `PR_SET_DUMPABLE=0`（封死 `/proc/pid/mem`）；**双线程 ptrace 互锁**（自己 ptrace 自己，别人 attach 即失败）；inotify 监控 `/proc/self/status` 的 TracerPid 变化 |
| **L3 反 dump** | 阻止内存读取工具 | gameguardian / `process_vm_readv` / 直接读 mem | inotify 监控 `/proc/self/mem` 访问（已有，增强）；**检测 `process_vm_readv` 系统调用**（seccomp 或 syscall 计数）；检测 `/proc/pid/mem` 被 open 的 fd |
| **L4 运行时完整性** | 断点 / patch 立即暴露 | 硬件断点 / 软件断点(BRK) / 内存 patch | 守护线程持续 CRC 校验 **.text + .rodata + .got.plt** 三段；软件断点改 .text 字节 → CRC 不匹配 → kill；硬件断点通过读 DR0-DR3 寄存器检测 |
| **L5 SMC 自修改** | dump 出来也是乱码 | 内存 dump 后离线分析 | 2-3 个核心函数（签名校验 / hash 计算）运行时 **XOR 自修改**：空闲时 .text 是密文，执行前 XOR 还原，执行后 XOR 回密文。dump 时机几乎必中密文态 |

### 4.2 五层协同逻辑

```
攻击者想 dump 内存
  → 先要注入 Frida        → L1 拦
  → 或 attach GDB         → L2 拦
  → 或读 /proc/pid/mem    → L3 拦
  → 或下断点单步          → L4 拦（断点改字节，CRC 报警）
  → 即使全绕过拿到 dump   → L5 兜底（核心函数是 XOR 密文）
```

### 4.3 玄甲的诚实边界

玄甲不用自实现 Linker，因此**非核心** .text 段确实是正常 ARM 指令（IDA 理论上能反编译）。玄甲通过 L1-L4 让攻击者**到不了** IDA 分析那一步，L5 让最值钱的核心函数即使到了也看不懂。这是"门禁"的周全之处。

**玄甲 = 五层门禁 + SMC**（周全，对抗 ~95% 实战攻击）。
**天衍 = 五层门禁 + SMC + 迷宫**（极致，对抗专业逆向团队）。

## 5. 字符串加密方案（玄甲 = 路径 1，天衍 = 路径 2+3）

### 5.1 为什么"MT 解不开"是核心要求

MT 管理器「字符串解密」原理：扫描 `.rodata/.data`，找连续 ASCII/UTF-8 序列，尝试 XOR / 移位 / Base64 / RC4 等**已知简单算法**还原。**它能解开的 = 加密算法在它数据库里**。

因此"MT 解不开"意味着：用**它数据库里没有的算法**，或**让解密函数本身不可被 hook/分析**。

### 5.2 三条路径

| 路径 | 技术 | 对抗级别 | 归属 |
|------|------|---------|------|
| **路径 1：编译时多态加密** | 每个字符串用不同随机 seed + 随机算法变体（XOR/ROL/ADD/MUL 四原语 × 24 排列 × per-string seed，亿级多态空间）。解密函数是普通 C 代码，但每个字符串解密逻辑不同，自动化破解成本高 | MT/NP 一键解密**完全失效**（依赖已知算法模式匹配，多态打破前提） | **玄甲** |
| **路径 2：路径 1 + VMP 保护解密函数** | 解密函数本身被 VM 字节码化。MT/NP 即使找到解密函数入口，hook 后拿到的是 VM dispatch，无法直接获取明文；用后 memset 清零 | 对抗手动 hook 解密函数 | **天衍** |
| **路径 3：路径 2 + 字符串分段散列存储** | 字符串拆 2-4 段分散在 .so 不同 section，运行时动态组装 + VMP 解密 + 用后清零。即使 dump 内存也只能拿到片段 | 对抗内存 dump + 离线分析 | **天衍高级** |

### 5.3 加密对象范围

| 加密对象 | 玄甲 | 天衍 | 合规依据 |
|---------|:----:|:----:|---------|
| SDK 自身 .rodata 字符串（"frida"、"/proc/self/maps" 等） | ✅ 路径 1 | ✅ 路径 2+3 | ADR 0077 允许（SDK 自身） |
| 用户 Java/Kotlin 代码中的字符串常量 | ❌ v1.0 不做（v1.1 经 ADR 0090 评估） | ✅ T4（经 ADR 0090） | 需 ADR 0090 授权 |

> **玄甲 v1.0 字符串加密 = 路径 1，仅加密 SDK 自身字符串。** 用户 DEX 字符串加密属加固流程修改，必须走 ADR 0090，归天衍 T4 / 玄甲 v1.1。

## 10. 差异化优势

| 维度 | ShadowSafety | 小城笺·玄甲 | 小城笺·天衍 |

## 14. 决策记录（本规划收敛过程）

1. **产品分界线** = 方案 A+B 混合：玄甲给完整 SDK 防护 + SO 加密 + 五层反动态分析（开源精神）；天衍卖加固引擎 + 托管方案 C + 绕过演练。
2. **玄甲 SO 必须加密**：避免玄甲明文 .so 成为天衍攻击者的分析样本。
3. **玄甲反动态分析必须周全**：采用五层纵深 + SMC，哲学"门禁+陷阱"，与天衍"迷宫"形成强度分级而非能力残缺。
4. **字符串加密分法**：玄甲 = 路径 1（多态），天衍 = 路径 2+3（多态 + VMP + 分段散列）。玄甲路径 1 已使 MT/NP 一键解密完全失效。
5. **用户 DEX 字符串加密**：玄甲 v1.0 不做（守 ADR 0077），天衍 T4 做（经 ADR 0090）。
