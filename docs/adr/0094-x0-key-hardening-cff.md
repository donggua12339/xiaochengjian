# ADR 0094: X0 密钥加固 + 控制流混淆框架(Hikari)

- **状态**: accepted(2026-07-26 真机验证:CFF 密钥重建+Hikari 混淆编译通过,四步流水线密钥不落盘)
- **日期**: 2026-07-25
- **决策者**: 用户 + Claude
- **关联**: ADR 0092(X0 SO 加密), ADR 0093(X4 反动态), ADR 0091(玄甲/天衍)

## 背景

Tier1 对抗测试(2026-07-25)中,红方通过静态反汇编 xcj_loader.so(8KB)的 JNI_OnLoad,
5-10 分钟即可提取 .rodata 中的 RC4 明文密钥。X0 加密形同虚设。

根本矛盾:解密者必须拥有密钥,而解密者运行在攻击者控制的设备上。
目标不是"不可提取",而是"提取成本 > 攻击收益"。

## 决策

### 1. 安全目标

| 产品线 | 提取成本目标 | 威胁模型 |
|--------|-------------|---------|
| 玄甲(免费) | 分钟 → 小时~天级 | MT/NP 一键脱壳 + 脚本小子 + 独立逆向者 |
| 天衍(付费) | 天 → 周级 | 专业逆向团队 |

### 2. 密钥保护架构(玄甲)

**(A) 混淆存储 + (B) 运行时派生 组合:**

```
derived_key = KDF(SO_base ⊕ text_crc ⊕ build_id ⊕ salt)
```

- SO 基址: ASLR 随机,静态不可知
- .text CRC: 复用 patch_x0 已有计算,构建期嵌入预期值
- build_id: 从 .note.gnu.build-id 读取,伪装成"ABI 兼容性检查"
- salt: 构建期随机,伪装成"日志随机种子"

### 3. 伪调用 + 数据流伪装(Q7)

(a) 功能伪装: 函数名/注释/日志全部伪装成非密钥功能
(b) 数据流伪装: 因子经 3-4 层无意义变换
(c) 控制流伪装: 派生链拆 5+ 函数,看起来像初始化序列

### 4. 控制流混淆(CFF)— 9 条手段(玄甲)

| # | 手段 | 对抗目标 |
|---|------|---------|
| 1 | 多层嵌套扁平化(套娃调度器) | 识别分发器 |
| 2 | 分发器形态多样化(if-else/函数指针/查表/计算goto) | 识别分发器 |
| 3 | state 即时计算表达式 | 追踪 state 流转 |
| 4 | 基本块切碎(10→40 块) | 提取基本块 |
| 5 | 代码块重复进入 | 提取基本块 |
| 6 | 不透明谓词 + 僵尸代码(BCF) | 提取基本块 |
| 7 | 虚假控制流 | 提取基本块 |
| 8 | 多状态变量协同(stateA/B/C) | 追踪 state 流转 |
| 11 | 不透明谓词保护跳转关系 | 重建控制流 |

天衍额外: 9(状态变量加密存储) + 10(反模拟执行) + 12(控制流数据流耦合)

### 5. state 转移函数

- 玄甲: (c) 查表 + LCG 混合,奇偶步交替,构建期随机表+参数
- 天衍: (d) AES_encrypt(state, build_key),不可逆

### 6. MVP 范围(3 个,直接对抗 RC4 key 提取)

1. CFF(1-9 叠加) — 密钥派生函数平坦化
2. 数字混淆 — key/salt/常量变运行时计算表达式
3. 伪调用 + 数据流伪装 — 派生链伪装成初始化序列

### 7. 实现形态

三脚本分工:
- `native_cff.py`: C 层 CFF + 数字混淆 + 伪调用生成(玄甲核心)
- `java_obf.py`: Java 层字符串加密 + 资源 ID + 反射保护 + 方法隐藏(后续)
- `so_packer.py`: SO 层指令替换 + 数据段混淆(天衍,依赖 OLLVM)

### 8. 构建流水线集成

```
SDK 源码 → native_cff.py(CFF+数字混淆) → obfstr_poly.py(X1 字符串) → CMake 编译 → .so
```

CFF 先于 X1(先改结构再改字面量)。

### 9. 混淆标记

JSON 配置文件 `hikari.json`(构建期读取,标记哪些函数/类要混淆):
```json
{
  "cff": ["xcj_derive_pad", "xcj_check_abi_compat", "xcj_init_log_seed", "locate_and_decrypt"],
  "number_obf": ["X0_KEY", "X0_KEY_LEN", "SO_CIPHER_MAGIC"],
  "string_enc": true
}
```

### 10. 天衍增量(后续)

- (C) 服务端下发密钥,离线降级到 (A)+(B)
- OLLVM 全量 CFF(-bcf -fla -sub)
- AES PRNG state 转移
- 反模拟执行对抗
- 控制流与数据流耦合

### 11. 验证

红方 Agent 重测: 混淆后让红方重新反汇编 xcj_loader.so,记录提取 key 时间。
目标: 从 5 分钟 → 数小时~天。

## 后果

- 构建期增加 native_cff.py 步骤(零额外构建命令,集成进 CMake 自定义命令)
- xcj_loader.so 体积从 8KB → ~12-16KB(CFF 膨胀)
- 启动时间增加 < 1ms(派生计算极轻)
- 每次构建 CFF 随机化,二进制不可复现(和 X1 一致)
