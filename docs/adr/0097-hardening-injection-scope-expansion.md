# ADR 0097: 加固注入范围扩展——用户自有 APK 全量注入 + 风险自担声明

- **状态**: accepted
- **日期**: 2026-07-29
- **决策者**: 用户(项目所有者)
- **关联**: ADR 0081(七锁架构), ADR 0088(defender-sdk 集成), ADR 0090(保护性混淆授权)
- **修订关系**: 部分修订 ADR 0081 锁 2 的适用范围

## 背景

ADR 0081 锁 2 原约束:"仅注入固定 classes-xcj.dex，禁止扩展为自定义 smali 或非 SDK 注入"。

此约束限制了加固功能的实用性——用户无法通过网页端一键将玄甲/天衍的保护能力集成到自有 APK 中，只能手动集成 SDK。

## 决策

### 变更内容

将加固注入范围从"仅注入固定 SDK DEX"扩展为"可注入用户自有 APK"：

| 维度 | 变更前(ADR 0081 锁 2) | 变更后(本 ADR) |
|------|----------------------|----------------|
| DEX 注入 | 仅固定 classes-xcj.dex | 可修改用户 DEX(字符串加密/指令替换) |
| SO 注入 | 固定 defender.so + 30 池随机名 | 不变 |
| smali 修改 | 禁止 | 允许(仅限保护性修改,ADR 0090 授权范围) |
| Manifest | Application 委托 + meta-data + provider | 不变 |
| 签名 | 自备 Keystore V1+V2+V3 | 不变 |

### 新增合规约束

1. **用户自有声明**: 用户必须勾选"我确认此 APK 为我自有或已获合法授权"，声明记录入审计日志
2. **风险自担**: 若用户擅自上传他人 APK 进行加固，用户个人承担全部法律责任，平台不承担任何连带责任
3. **保护性修改限制**: smali 修改仍限于 ADR 0090 授权范围(const-string 替换 + 解密调用插入)，不改业务逻辑
4. **免责声明展示**: 前端加固页面必须在执行前展示免责声明，用户确认后方可继续

### 保留的红线(不变)

- 守城军规 I-IV 全部保留
- 禁止通用脱壳/通用去签/伪装身份
- 禁止对非自有 APK 提供加固服务(技术上不做校验，法律上由用户声明兜底)

## 后果

- 正面: 用户体验大幅提升，网页端一键加固成为可能
- 负面: 法律风险转移至用户声明，平台需保留声明记录作为免责证据
- 技术: 无新增技术风险(注入逻辑已有 T4 encrypt-strings 验证)

## 审计要求

每次加固操作必须记录:
- 用户 ID + 时间戳
- 用户声明确认(布尔值)
- APK 包名 + SHA-256
- 选择的加固模块列表
- 操作结果(成功/失败)
